# PHOSPHOR 联机（局域网）设计

本文定义**引擎侧的联机能力**：传输层、发现、线程模型、暴露给卡带的 `phos.net` API。
它遵守项目既有铁律（分层、单一真源、沙箱安全），并且**刻意不做同步模型** —— 锁步、
行动中继、主机权威都是卡带的选择，引擎只保证"能把消息可靠地送到对面、并如实报告连接状态"。

> **一句话**：引擎给一条**带房间概念的可靠管道**（TCP 星型 + 主机中继）和**局域网发现**
> （UDP 广播），卡带在这上面自己搭协议。引擎不掺和"谁该在第几帧做什么"。

---

## 一、目标与非目标

**目标**

- G1 **连接**：主机开房 / 客人加入（局域网内，手动 IP 或自动发现）。
- G2 **收发**：给对端发一条带"类型 + 数据表"的消息；收到时能知道**是谁**发的。
- G3 **房间**：多个客人；主机中继，客人之间也能互发（星型拓扑，见第四节）。
- G4 **发现**：局域网内自动列出"正在开房的房间"（名字 / IP / 端口 / 人数）。
- G5 **可观测**：连接状态、对端列表、往返时延（RTT）、最近错误，卡带都能读。
- G6 **沙箱安全**：卡带拿不到裸 socket；消息有大小与速率上限；坏消息不解码崩溃。
- G7 **零回归**：不碰 `Screen` / `Renderer` / 现有任何卡带；不联网时这套东西完全休眠。

**非目标（本世代不做）**

- **不做同步模型**：锁步、回滚、行动中继、状态快照都留给卡带（见第九节）。
- **不做 NAT 穿透 / 中继服务器**：局域网直连；跨网段不在范围。
- **不做可靠 UDP / 有序 UDP**：实时性要求高的场景将来再说（第十五节）。
- **不做加密**：局域网、明文；敏感数据不属于本机定位。
- **不做卡带之外的网络入口**：主机脚本 / 启动动画也能调 `phos.net`，但同样只有这套 API。

## 二、分层与依赖

新增两个模块，都**向下依赖**，符合 `architecture.md` 的铁律：

```
        api/            register_net_api：把 Net 包成 phos.net（卡带唯一的联机入口）
         │
        net/            Net：连接生命周期 / 房间 / 中继 / 分帧 / 发现 / 线程（引擎逻辑）
         │
     platform/          socket.{hpp,cpp}：WinSock/POSIX 的**唯一**落点（铁律：OS 相关集中在此）
```

- `platform/socket.*`：只有它 `#include <winsock2.h>` / `<sys/socket.h>`。TCP/UDP 薄封装 + `select`。
- `net/*`：不碰系统调用细节，只用 `platform/socket`；不 include `sol`/`lua`。
- `api/net_api.*`：只做 Lua ↔ 值转换（表 ⇄ JSON），不含任何网络逻辑。
- `core/App` 持有 `Net`（组装点），并把它注入 `HostContext`；**卡带卸载时停止联机**。

> 与既有 `agent/control_channel`（NDJSON 调试通道）的关系：两者都走 socket，但**用途与
> 生命周期完全不同**。`control_channel` 是"人在环"的调试口、只绑回环；`net` 是卡带的
> 游戏通道、要绑局域网。它们**不共用代码**（各自封装各自的 socket），避免把调试口的安全
> 假设（只回环）泄漏进游戏通道。

## 三、传输、拓扑与房间

- **传输**：TCP（可靠、有序）。局域网单跳，延迟低，回合制与锁步都够用。
- **服务发现**：UDP 广播（第六节），只用于"找到房间"，不承载游戏消息。
- **拓扑**：**星型 + 主机中继**。主机是唯一的中心；客人只与主机有 TCP 连接。客人发给
  另一个客人的消息，由主机**转发**。这样：

  - 客人只需一个连接（NAT / 防火墙友好）；
  - "谁在线"由主机一处维护，不会各说各话；
  - 一致性简单：主机是房间里消息的中枢。

- **对端 id**：主机恒为 `1`；客人依次拿 `2, 3, …`（连接时由主机分配并在握手告知）。
  `0` 保留作**广播地址**（`send(0, …)` = 发给除自己外的所有人）。
- **上限**：默认最多 8 个客人（`max_peers`），可配；超出的连接被拒绝并断开。

## 四、线程模型（理解"为什么主线程不阻塞"的关键）

与 `core/audio` 同一套心智：**主线程只入队/取队，网络跑在后台**。

- **网络线程**（每 `Net` 一条）：用 `select` 同时看守 监听套接字 + 各对端 TCP + 发现 UDP，
  超时几十毫秒：
  - 可读的 TCP → `recv` 进帧缓冲 → 切出完整帧 → 解析 → 投递到**收件队列**；
  - 可写的 TCP（发送积压）→ 继续把**发件队列**里该对端的数据写出去；
  - 可读的 UDP → 处理发现查询/应答。
- **主线程**：`send()` 只把消息塞进发件队列；`poll()` 只把收件队列整批取走（swap）。
  两个队列用互斥量保护——锁的粒度是"入队/换队一次"，不覆盖任何阻塞调用。
- **`Net` 析构 / `stop()`**：置停止标志 → 关闭监听与对端（让 `select` 立刻返回）→ join 线程。
  与 `ControlChannel::stop()` 同一套"先摘牌、再关句柄、最后 join"的顺序，避免关到已换掉的句柄。
- **绝不**在主线程做网络 I/O；`discover()` 是唯一例外（它是有界的短阻塞，见第六节）。

## 五、消息格式与分帧

**TCP 帧**：`[uint32 大端长度][JSON 字节]`。长度上限 `kMaxFrame = 16 KB`；超长直接断开
（坏客户端不能让主机分配任意内存）。

**JSON 载荷**（每条一个对象）：

| 字段 | 含义 |
|---|---|
| `t` | 帧类型（引擎内部：`hello` / `welcome` / `msg` / `ping` / `pong` / `peers`） |
| `k` | 游戏消息的**类型串**（卡带自定义，如 `"shot"` / `"chat"`） |
| `to` | 目标对端 id（`0` = 广播）—— 只在"客人→主机"的上行帧里出现 |
| `from` | 发送者对端 id —— 由主机在转发时**统一填写**，客人不能伪造 |
| `d` | 游戏数据（任意 JSON 值；卡带侧是 Lua 表） |

- **握手**：客人连接后发 `hello{name}`；主机回 `welcome{id, host_id, peers[]}`。
  之后主机在有人进出时向全体广播 `peers[]`，于是每个客人都能维护对端列表。
- **`msg` 路由**（主机侧）：收到客人上行 `msg{to,k,d}` → 填 `from` →
  `to == 0` 广播给其他所有人、`to == 自己` 本地投递、否则转发给那个客人。主机自身
  `send` 同理。
- **RTT**：主机与客人互相周期性 `ping`/`pong`（带一个序号），引擎算往返时延，`peers()`
  里报 `rtt_ms`。心跳同时充当**保活**：连续多轮无响应判对端掉线。
- **坏帧**：长度越界、JSON 解析失败、`t` 未知 → 丢弃该帧（记一次日志），**不崩溃**。

## 六、发现（UDP 广播）

一个约定的发现端口（默认 `45454`，可配），叫 **DISCO**。

- **主机**：绑 DISCO（`SO_REUSEADDR` + `SO_BROADCAST`），监听查询；收到
  `{"magic":"PHOSPT","q":1}` 就**单播**回 `{"magic":"PHOSPT","name":…,"port":游戏端口,"players":n}`。
  另可选：主机每 ~1.5 秒主动广播一次同样的 beacon（丢包也能被看到）。
- **查询方**：`phos.net.discover(seconds)` 先把查询**广播**到 `255.255.255.255:DISCO`
  （并附发一份到 `127.0.0.1:DISCO`，同机自测也能用），然后在 `seconds`（默认 0.5s）内
  收集应答，返回房间列表。
- `discover` 是**有界阻塞**（默认半秒），只在卡带主动调用时发生；不是后台常驻。

## 七、`phos.net` API（卡带侧）

坐标与命名沿用项目习惯（`snake_case`）。所有函数对非法参数与"未联机"状态**安全返回**
（`false` / 空表 / 空串），不抛 Lua 错误——卡带不必写防御代码。

```lua
-- ── 生命周期 ────────────────────────────────────────────
phos.net.host(opts?)            -- 开房。opts: { port=7770, name="P1", max_peers=8,
                                --        discovery_port=45454, discoverable=true }
                                -- 返回 true/false；失败原因见 phos.net.error()
phos.net.join(address, opts?)   -- 加入。opts: { port=7770, name="P2" }
phos.net.stop()                 -- 离开 / 关房
phos.net.status()               -- "off" | "hosting" | "connecting" | "connected" | "error"
phos.net.error()                -- 最近一次错误串（无则 ""）

-- ── 房间与自身 ──────────────────────────────────────────
phos.net.role()                 -- "none" | "host" | "client"
phos.net.self_id()              -- 自己的对端 id（未联机 0）
phos.net.host_id()              -- 主机对端 id（未联机 0）
phos.net.port()                 -- 游戏 TCP 端口（未联机 0）
phos.net.local_ip()             -- 本机在局域网里的地址（提示用）
phos.net.connected()            -- 是否已连上（主机=已开房；客人=已连上主机）
phos.net.peers()                -- {{ id, name, address, rtt_ms }, ...}（不含自己）

-- ── 消息 ────────────────────────────────────────────────
phos.net.send(to_id, kind, data?)     -- 发给某对端；to_id=0 = 广播给其他所有人
phos.net.broadcast(kind, data?)       -- 等价 send(0, kind, data)
phos.net.poll()                       -- 取本帧收到的消息：{{ from, kind, data }, ...}

-- ── 事件（连接变化；与消息分开，便于大厅 UI 用） ──────────
phos.net.events()                     -- {{ type="connected"|"disconnected", peer, name }, ...}

-- ── 发现 ────────────────────────────────────────────────
phos.net.discover(seconds?)           -- 广播查询并收集应答：
                                      -- {{ name, address, port, players }, ...}
```

约定：

- `data` 是**可 JSON 化的 Lua 表**（number/string/boolean/嵌套表；深度上限 8，与
  `debug_state` 同族规则）。省略即空表。
- `kind` 是卡带自定义的类型串，引擎不解释它（除保留前缀 `net.` 不给卡带用）。
- `send` 在未联机或对端不存在时返回 `false`；`poll`/`events` 每次调用**清空**已读队列
  （与输入文本"本帧"语义一致：每帧调一次）。
- 主机也要 `poll()` 自己收到的消息——本地投递（发给主机、或主机发的广播别人回给主机）
  会进同一个队列。

## 八、沙箱与安全

- 卡带**拿不到 socket / IP 绑定的完全控制**：只能开房/加入/收发/发现。地址与控制面
  收窄成"目标对端 id"，客人不能直接指定"发给哪个 IP"。
- 单帧 ≤ 16 KB；`send` 的数据超限直接拒绝（返回 false）。收件队列有上限（如 1024 条），
  满了丢弃最旧的并计数——不让对端用消息洪水吃爆内存。
- 发现的 UDP 应答有大小上限、只解析固定字段；畸形包丢弃。
- 联机**默认关闭**：卡带不调用 `host/join` 就完全不占端口、不起线程。
- `App` 在卡带卸载 / 主机退出时调用 `net.stop()`，不把端口带到下一张卡带。

---

## 九、与确定性/同步的关系（为什么引擎不掺和）

引擎提供的是**管道**，不是**一致模型**。卡带要联机，自己选：

| 同步模型 | 卡带怎么做 | 引擎需要提供什么 |
|---|---|---|
| 行动中继（回合制友好） | 只在"该谁行动"时把该行动的输入/结果发出去，对方镜像 | 仅 `send/poll` |
| 确定性锁步 | 双方同 seed 跑同一逻辑，只交换每帧输入 | 仅 `send/poll` + 卡带自己的 seed 约定 |
| 主机权威 | 主机算，广播状态快照 | 仅 `send/poll`（快照序列化由卡带负责） |

**确定性的坑**（本文档记录，供卡带作者与将来的引擎增强）：

- 沙箱开了 Lua 的 `math` 库，`math.random` **不受 `phos.sys.seed` 控制**。锁步卡带要么
  一律用 `phos.sys.random`，要么自行同步种子（将来可考虑在沙箱里把 `math.random`
  接到主机 RNG 上——那时再改设计）。
- 浮点在**同机同构建**下可复现；跨平台/跨编译器不保证逐位一致。局域网内建议同版本二进制。
- **挂钟时间**（`phos.sys.time`）不能进逻辑；用逻辑帧号 `phos.sys.frame`。

## 十、与既有模块的边界

- `net` **不碰** `Screen`/`Input`/`Audio`：它只递字节，画什么、怎么响由卡带决定。
- `net` **不碰** `agent`：调试通道与游戏通道互不影响（不同端口、不同线程、不共享状态）。
- `net` 的错误**只通过 `phos.net.error()` 与日志**表达，不进入主机错误屏——联机失败是
  卡带的事，不该像"卡带脚本崩了"那样拔卡。

## 十一、分阶段与验收

| 阶段 | 内容 | 怎么验 |
|---|---|---|
| P0 传输 | `platform/socket` + `net` 的 host/join/收发/分帧 | 单机回环：主机+客人两进程互发一条消息 |
| P1 房间 | 中继、对端列表、id 分配、`peers` 广播 | 三进程：主机 + 两客人，客人互发经主机中转 |
| P2 发现 | UDP 查询/应答、`discover()` | 主机 + 客人 `discover(0.5)` 能看到房间的 name/port |
| P3 观测 | RTT 心跳、保活剔除、`events()` | 杀掉客人，主机 `peers()` 掉线、客人侧 `events` 收到 disconnected |
| P4 API 打磨 | `phos.net` 全套 + 参数校验 + 文档 | `tools/fixtures/net` 夹具卡带 + `tools/net_smoke.py` 全绿 |

**验收门禁**：`tools/net_smoke.py`——同机起两个（甚至三个）`phosphor` 进程，一个开房、
其余加入（含用 `discover` 自动找到），断言：能互发消息、对端列表正确、断开后有事件、
不联网时 `phos.net` 全为安全空值。

## 十二、将来（记录，不堵死）

- **可靠 UDP / 有序 UDP**：给实时性要求高的卡带（第十五节之外）。
- **`math.random` 接管**：让沙箱 RNG 与 `phos.sys.seed` 统一，锁步更省心。
- **更多传输后端**：现在只有 TCP；将来若要低延迟，`net` 内部换传输，`phos.net` 不变。
- **房间口令 / 观战位**：属于协议层，卡带先用 `data` 自己实现即可。
