# PHOSPHOR 设计愿景

> 未来城市的某个角落，一间荒废的游戏厅。
> 大多数机台早已熄灭，只有一台还亮着——
> 荧光绿的字符在布满灰尘的显像管上缓缓呼吸，等待有人插入一张卡带。

PHOSPHOR 是一台虚构的 ASCII 字符游戏机。它是一套**游戏运行时**（而非游戏合集），
通过加载用户自制的"卡带"来运行游戏，通过加载"内容包"来改变自身的一切外观与行为。

---

## 一、项目身份

- **它是什么**：一个有强烈主题氛围的 Fantasy Console 运行时（类似 PICO-8 / TIC-80 精神的字符终端版）
- **它不是什么**：不是模拟某个真实历史机型的模拟器，不是游戏引擎，不是游戏合集
- **技术形态**：C++17 + OpenGL 桌面程序（Windows 优先），Lua 作为卡带脚本语言

## 二、最高设计原则

以下原则是项目一切决策的裁判标准，优先级从高到低：

1. **万物皆可替换**
   用户在主机里看到、听到的一切（外壳、开机动画、配色、字体、音效），
   都应当可以被用户制作的内容包替换。主机自身只携带一套兜底用的默认内容。

2. **主机永不因卡带而死**
   卡带崩溃、卡带格式错误、内容包损坏——任何外部内容的错误都必须被捕获、
   报告，并让主机安全回到系统界面。崩溃只能是主机自身的 bug。

3. **Agent 是一等公民**
   字符屏幕本身就是纯文本，天然可被程序"阅读"。从架构第一天起，
   主机就必须支持无窗口运行、状态查询、输入注入与确定性回放，
   让 AI agent 能够自主完成"写卡带 → 运行 → 观察 → 调试"的完整闭环。

4. **卡带创作的低门槛**
   一张卡带最少只需要两个文件（manifest + main.lua）。
   API 设计的易用性优先级高于功能的丰富性。

## 三、体验效果清单

这些"感觉"是功能之外的验收标准。实现细节可变，感觉不可丢。

### 开机

- 按下电源，屏幕不是立刻亮起，而是像老显像管一样从中央一条亮线展开
- 随后进入启动动画（默认：BIOS 自检风格，逐行打印检测信息）
- 启动动画本身是内容包，可被完全替换

### 待机（未插卡）

- 屏幕上是缓慢飘动的雪花噪点，间或闪过主机 LOGO 的余影
- 机身灯珠以极低频率呼吸，仿佛在沉睡
- 有极轻微的环境音：电流嗡鸣、远处的城市噪声

### 插入卡带

- 屏幕出现一次"电压不稳"的闪烁与抖动
- 机身指示灯由呼吸转为常亮
- 卡带标题像终端登录一样逐字打出，然后进入游戏

### 游戏运行中

- 屏幕具有 CRT 质感：扫描线、轻微辉光、四角暗角、极轻微的曲面畸变
- 按下 Esc 呼出系统菜单时，游戏画面像被"压暗"成背景
- 拔出卡带（退出游戏）时画面收缩成一条线熄灭，回到待机

### 外壳与氛围

- 游戏屏幕占据窗口绝大部分，外圈是一圈占比不大的机身装饰
- 装饰不是静态贴图：灯珠会亮灭，装饰字符有微妙的动画
- 整体气质是"被时间遗忘但仍在运行的机器"，而非崭新的产品

## 四、生态愿景

PHOSPHOR 最终交付的不只是一个 exe，而是一套小型生态：

| 组成部分 | 说明 |
|----------|------|
| 主机运行时 | 本项目主体 |
| 内容包体系 | 皮肤 / 开机动画 / 配色 / 音效 / 字体，见 `content-packs.md` |
| 卡带体系 | `.phos` 单文件游戏包，见 `cart-format.md` |
| DevKit | 模板卡带、API 注解文件、打包工具、文档 |
| Agent 接口 | 命令行 + 控制通道，见 `agent-interface.md` |

**未完成事项的权威清单见 `roadmap.md`**（本文只描述"现在是什么样"，不再维护候选列表）。

**版本约定**：主机版本号唯一权威 = `core/version.hpp` 的 `kVersion`，
对内容作者暴露为 `phos.sys.version()` / `phos.sys.product()`。
卡带与内容包的 `version` 是作者自己的版本，与主机版本无关，两者不得混淆。
**任何地方都不得硬编码版本字符串**——这是"不硬编码"原则的第一个范例。

**可复用优先原则**：任何被两处以上使用的绘制、数值、路径，都必须先沉淀为
共享原语（`core/ui`、`core/defaults`、`core/text`）或 API（`phos.ui` 等），
再被调用方引用。发现"现场硬搓"重复实现即为缺陷，应重构而非复制。

**已知与初心的距离（按优先级）**：主机侧"让卡带创作不再需要改主机"的缺口清单
（见 `roadmap.md` 第五节）→ 像素/瓦片渲染通道（比字符更细的颗粒，见第六节）→
CRT 的暗角与曲面畸变 → 卡带架的显式排序（"最近玩过"已落地，还差 manifest 的排序字段）。
（字体/中文支持、字体包化、`phos.input.text()` 均已完成；卡带的玩法回归测试
已按决策整条移除——玩法由卡带作者自测，主机只保证"卡带怎么都弄不死主机"。）

## 六、非目标（明确不做）

- 不追求画面表现力上的"惊艳"，字符美学是约束也是特色
- 局域网联机已在第一世代之后落地（`phos.net`，见 `networking.md`）；**跨网段 / NAT / 云端仍不做**
- 存档以本地"磁带码"形式存在
- 不做卡带加密/DRM，开放与可折腾是本机的气质
- 不内置游戏，出厂只有演示卡带，游戏由创作生态产生
