### [~] 1. 字体与 CJK 双宽字符 —— **核心已落地**

已完成：

- `core/text`：UTF-8 解码、东亚宽度分类（W/F 区间）、按**显示宽度**的折行/截断/居中/补白
- `Screen`/`Cell`：新增 `cols`（1 半角 / 2 全角头格 / 0 续格）；写屏、清屏、`to_text`、跳过续格全覆盖
- 卡带 API：`phos.text.width` / `phos.text.truncate`；`screen.put` 单字符按码点解析（原先只取首字节）；
  侧栏与内容区按宽度裁剪（宽字符放不下就整体不画，不再溢出到机身）
- 渲染两条路径都支持：GL（ASCII 静态区 + 非 ASCII 按需装入动态区）与 CPU 光栅化（截图）
- `to_text` 的续格**不产出字符**：中文在文本里保持相邻（便于 agent 读屏与断言匹配）
- 卡带文案全部中文化（贪吃蛇 / 生命游戏 / 打砖块）；出厂字体随内容包提供，
  于是换一台机器也读得到同一套字形（同种子重跑可复现）
- 默认 CJK 字体随出厂方案提供：`theme/font/default/font-cn.otf`（思源黑体 SC，OTF/CFF
  轮廓，stb 可直接光栅化），角色命名与取字规则见 `theme/font/README.txt`
- 两套度量：主字体按行高缩放并确定像素基线；回退字体按 **em 方框** 缩放 + OS/2 排版度量对齐
  基线 —— CJK 字体的行高度量普遍大于一个 em，按行高缩放会让汉字只占约 0.7 格、明显偏小
- 渲染：全角字形在两格槽里居中；宽字符的底色整块两格一次铺完（续格不再单独铺底，
  否则会盖掉字形右半边）；GL 上传按 1 字节行对齐（否则字形逐行错位）

## 二、功能小口子（多为半天级）

### [x] 4. `phos.input.text()`

已落地：返回本帧文本（UTF-8，可含多字节字符与退格）。退格以 `text::kBackspace`（`'\b'`）送达，
**这是唯一约定**——窗口层负责把 Backspace 补进文本流（GLFW 的字符回调不会为它触发），
界面层用 `text::TextInput` 消费（过滤、按码点退格、限长、计数）。磁带码输入屏是它的第一个用户。

### [x] 5. 磁带码的系统菜单入口

已落地：暂停菜单 → `磁带码` → 查看页 / 输入页（左右切换），可滚动、可导入；
结果行由 `Shell::TapeResult` 回报语义（文案归界面层，跟界面语言走）。

### [x] 6. 卡带排序字段（"最近玩过"已落地，显式字段仍未做）

卡带架现在按**最近打开**排：插过卡的 id 记进主机同级的 `recent.txt`（最多 24 条），
`App::refresh_shelf_order` 扫描后按它 `stable_sort`，没开过的保持扫描顺序
（`core/app.cpp` 的 `sort_by_recent`）。

剩余：manifest 的显式 `sort` / `order` 字段、以及在界面里切换排序方式。

### [x] 8. `phos.assets` 大素材保护

已落地：`CartFiles::read` 加**单文件上限**（8 MiB，`kMaxReadBytes`），越限**拒读并写日志**；
`phos.assets.size` 改为**只查大小、不读全文**——于是"先问多大再决定读不读"不构成爆堆风险。
`exists` 也改走 stat / 目录项，超大文件如实报告存在（不再"读不动就谎报不存在"）。

**关于 400 行自省线**：它是"这块是不是该拆了"的信号，不是硬指标——优秀工程里上千行的
单个 `.cpp` 并不罕见。判断标准是**内聚**而不是行数：像磁带码界面那样"自成一整套状态机"
（两页、滚动、输入缓冲、结果行）就值得独立成文件，现已拆到 `shell/tape_view.cpp`；
而音频子系统虽 600 余行，其内容（波形 / 混音 / 设备）本就是一件事，硬拆只会把概念切碎。
当时（拆分刚完成）的实际行数快照：`core/audio.cpp` ≈ 561、`core/app.cpp` ≈ 425、
`shell/shell.cpp` ≈ 414 —— 只作历史参考，此后主线仍在改，别拿它当现状。

### [~] 17. App / HostContext 的收缩 —— 分阶段推进中

- App 的**实现**早已按职责拆在 `app_settings` / `app_intent` / `app_control` / `app_observe`
  / `app_cart` 里；头部成员多，是"主机把各子系统所有权集中在一处"的设计，大改需谨慎
- **第一步（已落地）**：内容包（皮肤 / 色板 / 开机动画 / 音效）的"有什么、选中哪个"抽成
  `pack/content_library.hpp` 的 `ContentLibrary`——App 不再直接持有 `skins_/palettes_/...`
  这些成员；扫描、按 id 定位、由主题解析色板各归一处，并补了单测（`resolve_palette` 纯数据、
  留头内联可测）。App 只保留"把选中项应用出去"（要动渲染 / 音频设备）
- **第二步（已落地）**：卡带逐帧耗时（update / draw / 峰值 / 图层合成）收成 `App::CartTiming`，
  带 `reset()`——换卡 / 拔卡一次归零（散落时正是漏了 `merge_ms` 出过"拔卡后仍报旧值"的 bug）
- **第三步（已落地）**：三块显示面（`screen` / `base` / `chrome`）与合成顺序抽成 `core/Display`；
  它只吃 `Renderer`（向下依赖）与整数原点、**不吃 `HostContext`**，因此是干净的分层单元
- **第四步（已落地）**：控制通道的**会话语义**（单步推进 / 待回包请求 / 注入按键定时释放）
  收成 `App::AgentSession`，与通道 I/O（`ControlChannel`）分开
- 详见 `architecture.md` 的"App 的分解（进行中）"
- **第五步（结论）**：卡带生命周期、音频事件、控制命令分发**不外抽**——它们要动
  shell/audio/net/input/host/control 多个协作者、且依赖 `HostContext`（api 层），而 `cart/`
  按分层只能依赖 `core/`：硬抽要么违反分层、要么造"换位置的上帝对象"，它们本就是组装点
  `App` 的职责。其中**纯的部分照抽**：卡带架排序 → `cart/cart_info.hpp` 的 `order_by_recent`
  （纯函数，已补单测）
- `HostContext` 按设计就是 API 层与 App 的共享上下文（指针 + 少量 POD）；收窄成访问器只增
  一层间接、不减少真实耦合，且要改动全部 API 绑定，暂不动
- 原则：**每次只抽一个内聚子系统，每步跑全门禁**，不做一次性重写

    每采样触发）已无分配（音符名走 SSO），故只在换曲/加载那一刻有理论爆音面。要做成
    严格的 RT-safe 需给"旧曲子"加一个主线程回收槽 + 音频门禁，收益低、风险高，暂不做
  * GL：`glReadPixels` 失败未检测；续格上的笔迹被跳过（宽头字形本就盖住那片）

## 五、主机侧缺口（让"只写卡带"成立还差什么）

来源：一次对照式自检（卡带 API 实测 + 性能实测，2026-10）。
结论：网格类玩法、固定面板自绘 UI、音乐音效、存档/磁带码、agent 观测——**今天只写卡带就够了**；

## 六、渲染演进：从字符网格到瓦片/像素层

### 现状（被什么限制）

- 画面模型是**字符网格**：80×45 格 × 16px = 1280×720，每格一个字形 + 前景/背景色
- **颜色已经是真彩**（每格 fg/bg 独立 RGB，`phos.color.*` 只是 12 个具名槽）——
  所以"不够细"的瓶颈是**分辨率与字形**，不是颜色
- 两条渲染路径共用同一份网格：GL（1024² 字形图集，ASCII 静态 + 非 ASCII 按需装入）
  与 CPU 光栅化（逐格 `fill_cell` + `blend_glyph`，用于截图/无头）
- 每个格子的字形分辨率因此固定在 **16×16 像素**以内

### 结论：**可以做到更细，但要新开一层"瓦片/像素通道"**

现有管线（格子 → 图集 quad → CRT 后处理 → 窗口）本身是通用的，
缺的是**第二个更细的画面模型**与对应的卡带 API。这类做法在幻想游戏机上很成熟
（PICO-8 / TIC-80 都同时提供低分辨率像素屏与瓦片/精灵 API），本机的最大优势是
**CRT 后处理与缩放管线可以原样复用**。

### 设计草案（NES / GB 那一类的分工）

1. 新增**索引位图屏**：典型 160×144（GB）或 256×240（NES），16/32 色板，瓦片可换色
2. 卡带 API **走瓦片/精灵优先，而不是逐像素**：
   - 逐像素全屏**不可行**：256×240 ≈ 61k 次 Lua 调用 ≈ 15ms，一帧预算直接见底（实测：3600 次 `put` ≈ 1ms）
   - 可行形态：`pix.spr(n,x,y,flip)`、`pix.map(cx,cy)`（C++ 一次画完整个可见瓦片图）、
     `pix.camera(x,y)`、`pix.pal(...)`，加上少量 `pix.pset/pget`
3. 图层合成：瓦片层在下、现有字符层在上（`phos.screen.*` 保持不变 → 既有卡带零改动）
4. CRT 后处理、截图（CPU 路径画索引位图更简单）、无头运行照旧支持
5. 工作量：**大**（新的视频模式：渲染器 + CPU 路径 + API + 文档 + 一张演示卡带）

### 今天就能试的"细一点"（不动主机）

- **方块字符当子格**：`█▀▄▌▐▚▞▖▗`（U+2580–259F）把一格当 2×2 甚至 2×4 用 → 等效分辨率翻倍；
  出厂回退字体是思源黑体 SC，通常含方块与制表符（**需实测覆盖**：缺字会以 `.` 占位）
- **按行 `print`**：一行 80 格一次调用，画地图最省（45 次调用/帧即可铺满整屏）
- 另一条路是**提高网格密度**（例如 160×90 格 × 8px），但皮肤/面板/CRT 参数都按 80×45 定的，
  改动面比新开一层还大，不推荐
