# PHOSPHOR 绘制模型：格 / 半格 / 叠加 / 底色

> 这讲的是**引擎**提供了什么能力；卡带怎么用见 [`../api-reference.md`](../api-reference.md)。

## 0. 一句话

把"一格 = 一个字"这条限制打开三个口子 —— **半格**（子格绘制）、**叠加**（同格多笔共存）、
**底色独立**（底色与字形分开控制）。这三件事曾经要卡带自己拼字符凑，如今是引擎能力。

## 1. 现状：谁在替引擎干活

| 需求 | 今天怎么凑 | 代价 |
|---|---|---|
| 半格绘制 | 卡带自带"象限字形表 + 位序"，把 4 个子位拼成一个字符 | 表与位序每张卡带各写一份；写反了就是"画在一处、判在另一处" |
| 同格多笔 | 一格只有一个字形槽，后来的必然盖掉先前的 | 视觉上丢掉一笔（`~` 落进 `-` 的那一格，只剩一个） |
| 底色独立 | `put(..., bg)` 会连字形一起换；`fill` 又总是整块写 | "背景比字形宽一格"这种需求要绕着写 |
| 半格对齐 | 相机原点落在**奇数**子格时，世界格边界在屏幕格正中，卡带自己算屏幕列 | 算错就是"画出来的位置跟着镜头漂" |

## 2. 目标

- **G1 半格**：卡带能用**子格坐标**落笔（一格 = 2×2 子位），字形合成由引擎负责。
- **G2 叠加**：同一格可以叠多笔，各自按**字形覆盖率**混合。"`~` 与 `-` 共存一格"是
  引擎保证的行为，不是卡带的技巧。
- **G3 底色独立**：底色能单独设置/成块铺，且**不动字形**。
- **G4 兼容**：不碰这三件事的卡带**逐字节不变**（沿用纯增量原则：新 API 不改变既有写入路径）。
- **G5 可断言**：三条各配契约门禁（读像素 + 读网格），并纳入 `--check-api`。

## 3. 设计

### 3.1 Cell：一格多笔

- `Cell` 增加 `inks`（上限 `kMaxInks = 3`）：一笔 = `{ ch, fg }`，与现有 `ch/fg` 同构。
- 写入语义分成两组，**默认仍是旧的那组**：
  * `put / print / fill / clear / blit` = **替换**（清空 inks）—— 现状不变；
  * `blend`（新）= **追加**一笔，不碰已有内容。
- 渲染：先铺底色，再按 inks **顺序逐笔**画（每笔按字形覆盖率 alpha 混合）——
  这就是"像素融合"：两笔的墨都在，重叠处后面那笔的颜色占优。
- 文本通道（`--dump-screen` / `screen.read` / `phos.screen.get`）：取**最前一笔**，
  与今天一致；文档写明"文本通道有损，颜色与叠加用 `screenshot` 或分层读"。

### 3.2 半格

- `phos.screen.plot(x2, y2, fg)`：按**子格坐标**落一笔（越界裁剪）。落到格 `(x2//2, y2//2)`，
  把该子位并进这一格 —— 已有笔迹时走 §3.1 的叠加，而不是覆盖。
- `phos.pixel.canvas(w, h)`：一块**子格画布**（`dot` / `mark` / `cell` / `flush`），
  供"一次攒很多子位、再整块落格"的批量场景（降水、星空、光柱）用，避免逐点调用。
- 位序**由引擎定义**（1 左上 / 2 右上 / 4 左下 / 8 右下），卡带不再自带表。
- 边界说明：子格是**屏幕空间**的；"世界 → 屏幕"仍是卡带自己相机的职责，
  引擎只保证"子格坐标 → 像素"精确、且与世界无关。

### 3.3 底色独立

- `region:back(x, y, color)`：只写这一格的**底色**（同时把"底色存在"打开），字形与 inks 不动。
- `region:back_rect(x, y, w, h, color)`：一整块只写底色。
- 现有 `put(..., bg)` 保留（替换语义，含底色）；`region:fill` 的"省略底色 = 保留"不变。

### 3.4 与图层的关系

图层解决"谁压在谁上面"，本设计解决"同一格里怎么共存"，两者正交：
层与层之间本来就逐笔叠（`Renderer::draw_layers`），现在**层内**也补齐同一条规则。

## 4. 边界（明确不做）

- **不做逐像素绘制**：画面抽象仍是"字符网格 + 子格"，不开任意像素的口子。
- **不做逐格半透明**：alpha 仍是"存在/不存在"；要半透用棋盘抖屏（见 [layers.md](layers.md)）。
- **笔迹有上限（3）**：它是"同一格叠几笔"的预算，不是图层系统。满了之后 `blend`
  **拒绝新的那一笔**（返回 false，日志只报一次），层合成则丢弃**最深处**的一笔 ——
  两者都不静默截断已有内容，卡带能从返回值知道"这一笔没画上"。

## 5. 分阶段与验收

| 阶段 | 改哪里 | 怎么验 |
|---|---|---|
| P0 引擎·多笔 | `core/screen.*`（笔迹表，`Cell` 不变）、`render/renderer.cpp`（逐笔）、`api/*`（`blend`） | 契约门禁：同格两笔的墨都在；不叠笔的帧不走这一趟 |
| P1 引擎·半格 | `api/draw_region.*`（`plot`）、`phos.screen.quadrant` / `cell_of`（位序与字形表归引擎）、注解与 `api-reference.md` | 契约门禁：`plot(2i+1, 2j+1)` 落在该格右下象限；`--check-api` 通过 |
| P2 引擎·底色 | `api/*`（`back` / `back_rect`） | 契约门禁：`back` 后字形与笔迹逐字符不变、底色变了 |
| P3 门禁 | `tools/draw_smoke.py`（契约级，不绑玩法） | 四项断言：文本取最前一笔 / 同格两笔的墨都在 / 底色独立 / 半格象限（另含叠画上限） |
| P4 卡带 | `carts/worms` 改用 `blend` / `plot` / `quadrant`，不再自带字形表与"同格二选一"画布 | 门禁全绿 + 截图人工比对：云压在太阳上两笔都在 |

## 6. 动机

卡带为这三件事各写一份凑法时，付出过一次真实代价：光柱的对齐由卡带自己算屏幕列，
算错的表现是"柱子跟着镜头漂"，而**测试抓不到**（门禁只看主机属性）。把这份几何收回引擎之后，
"世界→屏幕"只剩卡带相机一处、'子格→像素'只剩引擎一处，两边都可断言。

## 7. 现状

- `Cell` 本身不变：笔迹与子位累积走 `Screen` 的稀疏表，不叠笔、不落半格的卡带零开销。
- `blend` / `back` / `back_rect` / `plot` / `quadrant` / `cell_of` 已注册为 API 并配注解，
  `--check-api` 逐项一致。
- GL 渲染与 CPU 光栅化**两条路都按笔绘制**、合成顺序相同 —— 截图与开窗画的是同一张图。
- 层合成把下层字形压成笔迹：同一格里"下层的字 + 上层的字"是叠加，不是顶替。
- 门禁 `tools/draw_smoke.py`（八项，含叠画上限）；样板卡带 `package/devkit/examples/inks/`。
- `carts/worms` 用这套原语画天空、降水、地形：**位序与字形表只有引擎一份**。
  光柱仍按整字符格画，因为它的伤害判据就是整字符格（见 `carts/worms/DESIGN.md`）。
