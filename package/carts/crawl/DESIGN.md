# GLOW CRAWL (crawl) 设计文档（v1）

> 本文件是这张卡带的**唯一规格来源**：数值、字段名、公式、算法都以它为准。
> 改玩法先改这里，再改代码。随卡带一起打包（想只留源码就把它挪出卡带目录）。
>
> 类型：**回合制 Roguelike 地下城探索**。与出厂卡带（球球 / 炮击 / 象棋 / 方块 / 贪吃蛇 /
> 扫雷式吃豆 / 跑酷 / 生命游戏 / 打砖块）无一重复，也不与它们共用任何题材或机制。

## 0. 一句话与设计目标

**你提着一盏会熄灭的磷灯，往十层地牢的深处爬，去敲开守望者、取回"磷之心"。**
灯亮时你看得远，但怪物也看得见你；灯弱时你藏得住，却寸步难行。

设计目标，按优先级：

1. **可复现**：一切随机走 `phos.sys.random`，同种子逐位一致——测试与复盘靠它（§16）。
2. **系统的咬合**（这是复杂度标杆所在）：**光**同时是视野、是探测、是资源——
   灯油（loot）↔ 视野半径 ↔ 怪物察觉 ↔ 战斗风险，四个系统互相牵动，
   而不是四份互不相干的表。
3. **单屏地牢**：地图一屏画得下、无相机滚动（≤ 54×36），因此无坐标换算负担、
   玩家永远看得清全局，回合手感干净。
4. **可读性**：敌我一眼分色，伤害/掉落/升级都有日志（§11），死亡原因从不含糊。

**与 WORMS / BALLBATTLE 的关系**：只参考它们的**文件拆分方式**（manifest / main / 各系统模块 /
panel / music 分离）与质量档次，不借鉴任何玩法。

## 1. 核心循环 / 胜负 / 通关

```
进入一层 → 探索（灯塔照亮、捡物资、杀怪升级）→ 找到下行楼梯 > → 进入更深一层
        ↓ 深度 = 10
   击杀守望者 W → 拾取"磷之心" * → 通关
```

- **开局**：深度 1，玩家在起始房，磷灯满油（100），属性见 §6。
- **一层一次生成**：房间 + 走廊 + 新一批怪物/物品/金币（§4、§7、§9）。
- **回合制**：玩家每做一个动作（移动/攻击/等待/下楼/用物品）＝ 推进一步，
  怪物按能量调度器（§5）获得行动。
- **失败**：HP ≤ 0 → 死亡结算屏；可 `[A]` 重开。
- **通关**：深度 10 击杀守望者并拾取磷之心 → 胜利结算屏。
- **计分**：`score = gold + (depth-1)×150 + level×40 + (max_hp-24)×5`
  —— 金币、下潜深度、成长都算，鼓励"贪一点"。最高分写盘（§15）。

## 3. 地牢生成（`map.lua`）

**全部走 `phos.sys.random`，同种子同结果。**

### 3.1 房间

| 参数 | 值 |
|---|---|
| 房间数 | `R = clamp(rng_int(8, 13) , 8, 13)`，随深度微增：`+ floor(depth/3)`（上限 15） |
| 房间宽 | `rng_int(5, 11)` |
| 房间高 | `rng_int(4, 9)` |
| 房间间距 | 至少 **1 格**（边界不相接；房间含自身墙） |
| 放置尝试 | 每房最多 **40** 次随机投点，放不下就跳过（总尝试上限 600） |
| 柱子房 | 25% 概率在房内均匀撒 1~4 根单格柱子（`#`），让房间不是空盒子 |
| 门 | 走廊接入房间处 **35%** 概率保留一格门（`+`，仍是可通行地面，仅外观/日志用） |

放置算法：随机 `w,h` 与左上角 `(x,y)`（留 1 格边界），与已放房间矩形**外扩 1 格**求交，
不相交才落位。所有房间记录 `{x,y,w,h}`。

### 3.2 走廊

- 按**房间放置顺序**，把第 i 个房间连到"已连通集合里离它最近的那个房间"，
  形成一棵**生成树**（保证全图连通、无环、无死胡同迷宫感）。
- 走廊为 **L 形**：先横后纵或先纵后横（`rng` 决定），交点中心对齐两房中心。
- 走廊宽 **1 格**；**8%** 概率加宽为 2 格（并排），增加视觉层次。
- 走廊挖的是地板（`.`），覆盖到的墙自动变地板。

### 3.3 特殊格与放置

| 元素 | 规则 |
|---|---|
| 玩家起点 | 第 1 个房间中心（非柱子格）；`spawn_room = 0` |
| 下行楼梯 `>` | 放在**离起点欧氏距离最远**的房间中心；Boss 层（10）放 Boss 房中心 |
| Boss 房（仅第 10 层） | 强制生成一个 **13×11** 大房（先放），中心放守望者 + 楼梯在下行位，其余照常 |
| 金币堆 `$` | 每层 `2 + rng_int(0,3)` 处，随机房内空地上 |
| 物品 | 每层 `3 + rng_int(0,2)` 处（§9 权重表）；其中**保底 1~2 个灯油瓶** |
| 怪物 | §7 数量与图鉴；放在随机房内的**地块**上，且距玩家起点 `> 6` 格 |
| 保证可达 | 楼梯/物品/怪物只放**房间内地板**（生成树保证连通），不做孤立走廊 |

### 3.4 地形种类（tile id）

| id | 字形 | 含义 | 可通行 | 挡视线 |
|---|---|---|---|---|
| `WALL` | `#` | 岩壁 | ✗ | ✓ |
| `FLOOR` | `.` | 地面 | ✓ | ✗ |
| `DOOR` | `+` | 门（外观差异，可通行） | ✓ | ✗ |
| `STAIR` | `>` | 下行楼梯 | ✓ | ✗ |

水/岩浆之类**不做**：本作的地形复杂度集中在"光与感知"，不是地形交互（避免与 WORMS 的地形破坏重叠）。

## 4. 回合制时间模型（能量调度器）

采用经典 **energy（能量）** 模型，玩家动作驱动整个时钟。

**规则**：

- 每个存活实体有 `energy`（初值 0）与 `speed`（见 §7 表）。
- 一次"玩家动作"= 1 个 **tick**：
  1. 玩家执行该动作，`player.energy -= 100`；`turn += 1`；灯油 `fuel -= 1`（§10）。
  2. **所有**实体 `energy += speed`。
  3. 调度循环：反复取 **energy ≥ 100 中能量最高**的实体：
     - 若是**玩家** → 跳出循环，**等待下一次输入**（玩家重新"就绪"）。
     - 否则让该实体 `act()`，然后 `energy -= 100`；继续循环。
     - **平局时玩家优先**（同速怪物不会抢在玩家下一次输入前多打一下）。

**效果校验**（这是设计意图，实现要能对上）：

| 实体 | speed | 每 2 次玩家动作，它行动 | 手感 |
|---|---|---|---|
| 玩家 | 100 | 2 次 | 基准 |
| 巨鼠/哥布林/骷髅/兽人 | 100 | 2 次 | 1:1 |
| 洞穴蝠 | 150 | 3 次 | 快半拍，难缠 |
| 邪教徒 | 90 | 2 次（偶发慢拍） | 略慢，擅长远程 |
| 怨灵 | 70 | 1~2 次 | 慢，但穿墙 |
| 软泥 | 60 | 1 次 | 很慢 |
| 石魔像 | 55 | 1 次 | 慢、重击 |
| 守望者 | 110 | 2 次（偶发快拍） | Boss |

- 一次性动作（下楼、拾取地板物品）**也占一个 tick**（拾取本身免费，见 §9；只有"下楼"占 tick）。
- 击退/眩晕等状态**不做**（保持公式简单）。
- 死亡在**同一 tick 内**结算，死者不再行动；杀死最后一只怪不影响同一 tick 剩余实体。

## 5. 玩家属性与成长（`player.lua` / `combat.lua`）

### 5.1 一级属性

| 属性 | 初值 | 来源 |
|---|---|---|
| `hp` / `max_hp` | 24 / 24 | 升级增加；药水/干粮恢复 |
| `atk`（基础攻击） | 5 | 升级增加；武器加成 |
| `def`（基础防御） | 1 | 升级增加；护甲加成 |
| `level` | 1 | XP 满即升 |
| `xp` | 0 | 击杀怪物（§7） |
| `gold` | 0 | 金币堆 / 击杀掉落 |
| `fuel`（灯油 0..100） | 100 | 每 tick -1；油瓶 +50 |
| `weapon` / `armor` | nil / nil | 拾取装备自动装备（更强则替换） |

**有效属性**：`ATK = atk + (weapon and weapon.bonus or 0)`；
`DEF = def + (armor and armor.bonus or 0)`。

### 5.2 升级表

`xp` 为**累计**阈值（非增量）。达到即升级（可能连升）：

| 等级 | 累计 XP | 升级奖励 |
|---|---|---|
| 1 | 0 | 起始 |
| 2 | 16 | max_hp +6，atk +2，def +1，回复 8 HP |
| 3 | 42 | 同上 |
| 4 | 82 | 同上 |
| 5 | 140 | 同上 |
| 6 | 215 | 同上 |
| 7 | 310 | 同上 |
| 8 | 425 | 同上 |
| 9 | 560 | 同上 |
| 10 | 720 | 同上 |
| 11 | 900 | 同上 |
| 12+ | 每级 +220 | 同上（封顶 15 级） |

升级（含多级连升）时：逐级结算奖励，写日志 `> 升级！你达到 3 级。`（绿），播放升级音。

### 5.3 战斗与命中公式（**双方共用一套**）

设攻击方有效攻击 `A`，防御方有效防御 `D`：

```
命中率 hit% = clamp( 0.55 + 0.04 × (A - D), 0.15, 0.95 )
命中后基础伤害 = rng_int( ceil(A×0.75), A )          -- 波动型伤害
暴击          = rng_float() < 0.08 ，暴击则 ×2
最终伤害      = max(1, 基础伤害 - D)                  -- 暴击在减防前乘 2
```

- 未命中 → 日志 `> 你挥空了。` / `> 巨鼠扑空了。`（灰），无伤害。
- 命中 → 日志 `> 你击中巨鼠，-5 HP。`（白）／`> 巨鼠咬中你，-3 HP。`（红）。
- 所有取整用 `math.floor`/`ceil` 明确写在代码里，避免跨平台浮点差异影响**判定**：
  命中率比较用 `rng_float()`（`phos.sys.random(0, 9999)/10000`，`rng.lua` 封装），
  即"整数化后的随机"再比，保证同种子逐位一致。
- 20 点伤害是一个参照量（早期一发重击 > 半条命），数值全在上面，调平衡只动本表。

**死亡**：目标 `hp ≤ 0` → 从地图移除，给击杀者经验与金币：
`xp += spec.xp`；`gold += rng_int(spec.gold_min, spec.gold_max)`。
玩家死亡 → 结算屏（§1）。怪物死亡 → 写日志（白）+ 掉落金币（合并到下落位置的地面）。

**类型选择**：从"`depth_min ≤ depth ≤ depth_max`"的类型池里按 `weight` 加权随机。
Boss 层（10）恒有 1 只 `warden` + 其余按池（`golem/orc/skeleton` 为主）。

**特殊机制**（在 §8 AI 里实现）：

- `wraith` 命中玩家 → 额外吸走 **5 灯油**（日志：`> 怨灵吸走了你的光，-5 灯油。`，紫）。
  这形成核心张力：幽深处最怕且最该快点打掉的怪。
- `slime` 死亡 → 若 `depth < 9` 且场上 slime 总数 `< 6`，在其位置生成 **2 只小软泥**
  （HP = 母体上限的一半，ATK−1，XP/金币减半）；小软泥**不再分裂**（`split=false`）。
- `cultist` 命中/被逼近 → 见 §8 远程行为。
- `warden`：
  - **召唤**：每隔 **12 个玩家动作**（turn 计数）在相邻空地板召唤 1 只 `skeleton`
    （若相邻无空位则跳过），日志 `> 守望者张开骨骸之门！`（黄）。
  - **狂暴**：HP 降到 **< 30%** 时触发一次，`ATK ×1.5`、`speed = 130`，
    日志 `> 守望者的磷火暴燃！`（红）。
- 所有怪物**不重复刷**（层内数量封顶），不主动开新怪（除召唤/分裂）。

## 7. 视野 / 迷雾 / 磷灯（本作招牌系统，`fov.lua`）

### 7.1 光照半径（由灯油决定）

| `fuel` | 光照半径 `R` | 观感 |
|---|---|---|
| 67 – 100 | **9** | 明亮，看得远 |
| 34 – 66 | **7** | 正常 |
| 10 – 33 | **5** | 昏暗 |
| 1 – 9 | **3** | 将熄 |
| 0 | **2** | 只剩脚下一圈黑 |

- 每 **1 个玩家动作**消耗 **1 灯油**（走、打、等、下楼都算）。
- 油瓶 `+50`（封顶 100）；干粮 `+15`。一层保底 1~2 瓶油（§3.3）。
- 油量为 0 时顶栏与右栏的油条变红并闪烁（`(turn % 20) < 10` 决定亮暗），
  日志在**刚归零**时提示一次 `> 灯灭了。黑暗正在合拢……`（红）。

### 7.2 视野计算（FOV）

- 每次玩家动作 / 进层 / 拾取油瓶后**重算一次**可见集（地图小，成本可忽略）。
- 算法：**Bresenham 光线投射**——对以玩家为中心、`欧氏距离 ≤ R + 0.5` 的每个格，
  从玩家中心连线到该格中心，若中途被 `WALL` 挡住则不亮；否则可见。
- `visible[]` 每回合重建；`explored[]` **只增不减**（走过就记住）。
- 渲染三态：
  - 未探索：不画（保持色板 `black` 底）。
  - 已探索但当前不可见：地形用 **`dark_gray`** 画（记忆），**不画**怪物/物品。
  - 当前可见：地形/怪物/物品用**本色**画。

### 7.3 光与感知的咬合（核心张力）

- 怪物把玩家"看见"的条件：玩家在它的 `perception` 内 **且** LOS 通畅。
  - `perception` 基准 **8 格**；玩家光照 `R ≥ 9` 时 **+2**（你太亮，老远就被发现）；
    玩家 `fuel == 0` 时 **−2**（黑暗中你藏得住）。
- 也就是说：**灯亮 → 你看得远，怪物也看得远；灯灭 → 你寸步难行，但更隐蔽。**
  玩家要在这条曲线上管理灯油，而不是"油越多越好"的线性最优。
- 一旦被某怪发现，它进入 `awake`（记住玩家，持续追击）；若连续 **20 个玩家动作**
  没有 LOS，则 `awake=false`，回到 wander（防止跨图无限追杀）。

## 8. AI 行为规格（`ai.lua`）

所有怪物决策**只读世界状态**，调用 `map.lua` 的查询与 `phos.sys.random`，不绘制、不发声。

### 8.1 行为模式

| 模式 | 逻辑 |
|---|---|
| `sleep` | 未 `awake` 时不做动作（仅占用 tick）。被"看见玩家"或受伤时进入 `awake`。 |
| `wander` | 随机选一个相邻可通行格走一步；**不走进只有一个出口的格**（防死角，见 §8.3）。 |
| `chase` | 用 **BFS** 在感知范围内求到玩家（或最后已知位置）的最短路径，走第一步；相邻则 `attack`。 |
| `flee` | HP 分数 `< flee_at`（哥布林 0.25）时，选择"令与玩家距离最大"的相邻空格移动；无路则反击。 |
| `erratic` | 洞穴蝠：50% 概率随机方向移动，否则 chase（避开同一格来回抖）。 |
| `phase` | 怨灵：移动时**忽略 WALL**（可穿墙），但只沿 8 向、每步慢（speed 70）。 |
| `ranged` | 邪教徒：若 LOS 且距离 ≤ 5 → 发射磷火弹（用 §5.3 公式结算），否则若距离 < 3 则后退，否则 chase。 |
| `split` | 软泥：死亡时按 §6 生成小软泥。 |
| `summon`/`enrage` | 守望者：见 §6。 |

### 8.2 目标选择

- 玩家是**唯一**追击目标（本作单玩家，无多目标歧义）。
- `chase` 用玩家**当前位置**：有 LOS 时刷新 `known_x/known_y`，无 LOS 时用 `known_*`；
  `awake` 到期（§7.3）则清目标回 `sleep`。

### 8.3 防卡死（吸取 WORMS 的教训，写进规格）

1. BFS 求路而非贪心直走——贪心在 L 型走廊会贴着墙角抖。
2. `wander` 不进入"出口数 ≤ 1"的格（死胡同），被逼住（无合法步）时**允许原地等待**。
3. 怪物**不踩玩家格**：目标格是玩家时改为 `attack`。
4. 对角线移动要求**两个正交邻格都可通行**，禁止"贴角穿墙"。
5. 单帧 AI 计算上限：BFS 只在 `chase` 时对**单只**怪执行，范围 ≤ 感知半径；
   地图 ≤ 54×36，单次 BFS < 1ms，远低于 100ms 看门狗（§17）。

## 15. 随机数与确定性（`rng.lua`）

- **所有**随机走 `phos.sys.random`（禁用 `math.random`），封装在 `rng.lua`：

```lua
local R = {}
function R.int(a, b)   return phos.sys.random(a, b) end
function R.float()     return phos.sys.random(0, 9999) / 10000 end       -- [0,1)
function R.chance(p)   return phos.sys.random(0, 9999) < p * 10000 end
function R.pick(t)     return t[phos.sys.random(1, #t)] end
function R.range(a, b) return a + (b - a) * (phos.sys.random(0, 9999) / 10000) end
function R.shuffle(t)                                                    -- Fisher–Yates
  for i = #t, 2, -1 do local j = phos.sys.random(1, i); t[i], t[j] = t[j], t[i] end
  return t
end
```

- 运行种子：默认 `seed = phos.sys.random(1, 999999)`（**不主动** `phos.sys.seed`，
  以便主机 `--seed N` 仍能决定整局）；种子显示在顶栏与帮助浮窗。
- 测试复现：`phosphor --cart carts/crawl --headless --seed 42 --frames N`。
  同种子 → 同一层布局、同一怪物序列、同一战斗判定。**禁止**在生成/结算路径里
  用 `phos.sys.time` / `os.time` 之类非确定源。

## 17. 性能与看门狗

- 单帧上限 100ms。最坏帧：进层生成（房间 15 + 走廊 + FOV 一次）——实测目标 < 5ms。
- FOV 每玩家动作重算一次（≤ 54×36 光线，< 2ms）。
- AI 每 tick 每怪一次，仅 `chase` 做一次范围内 BFS（< 1ms/只）。18 只怪最坏 < 20ms。
- 渲染：全屏 ≤ 59×45 格逐格 `put`（实测 ≈ 1ms/3600 格），加右栏，远低于预算。
- 不做逐帧重算生成；地图/可见集都只在"需要时"重算（动作驱动，不是渲染驱动）。

   帮助浮窗 + 保底油 + 掉落解锁。
3. **第三刀**：Boss 层（守望者召唤/狂暴/磷之心）、`music`/`sfx`、双语日志全覆盖、
   `debug_state` 全字段、存档最高分、平衡微调。

## 19. 验收用例（第一/二刀门禁）

1. `--seed 42` 同一序列开局，两层布局与怪物位置逐位一致（跑两次 diff 输出）。
2. 走向墙不动；走向怪物触发一次攻击（命中或挥空）并有日志。
3. 每移动一格灯油 −1；光照半径在 66 / 33 / 9 / 0 的跨档处**恰好**按 §7.1 变化。
4. 怨灵穿墙到你身边命中一次 → 灯油 −5（日志出现）。
5. 软泥被击杀 → 生成 2 只小软泥（`debug_state.monsters` 计数 +2；小软泥不再分裂）。
6. 油瓶拾取 → fuel +50 且封顶 100；灯油为 0 时再等 5 回合仍能移动（半径 = 2）。
7. 拾取更强武器自动换装、旧装备落地（地上出现对应 item）。
8. 背包满（8 格）时再拾取消耗品 → 不拾取 + 日志"背包满了"。
9. 击杀足以升级 → 等级 +1、`max_hp` +6、HP 回复、日志"升级"。
10. 第 10 层击杀守望者 → 拾取磷之心 → `won = true`，结算屏出现；`debug_state.won`
    为 true 且 `best_score` 落盘。
11. `[Y]` 不在楼梯上 → 给出"这里没有楼梯"提示，不改变状态。
12. 记忆/可见三态：走出光照后地形变 `dark_gray`、怪物消失；再走回去恢复。
13. 无头文本：`--dump-screen` 下能看到 `@`、`>`、`$`、顶栏、右栏读数与日志行。

## 20. 风险与可选增强（不承诺实现）

- **平衡**：石魔像 / 守望者可能过肉。数值集中在 §6/§5.3，靠 `phos.debug` 暴露
  `玩家ATK/怪HP倍率/掉率` 三个旋钮实时微调（`main.init` 里 `phos.debug.number`）。
- **可选**：种子输入框（`phos.input.field`）做"指定种子开局"；暂停浮窗；
  击杀统计；多层"磷火"状态（点燃地形照明）。均在核心稳定后再议。
- **明确不做**：地形破坏（与 WORMS 重叠）、多玩家/联机（保持单机回合制）、
  逐格半透明（引擎不支持，用亮度分档代替）。
