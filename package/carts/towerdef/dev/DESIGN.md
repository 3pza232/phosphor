# CORE LINE / 磁芯防线 —— 设计文档（v1）

> 类型：塔防（grid tower defense）。id = `towerdef`。
> 这份文档是这张卡带的**唯一规格来源**：数值、字段名、算法以它为准。改玩法先改这里，再改代码。
> 目标复杂度看齐 `carts/ballbattle` 与 `carts/worms`（多系统相互作用、模块合计 1000+ 行）。

---

## 0. 一句话

在**可自由砌墙的网格**上布防：建塔、拉电、升级，挡住一波波冲向磁芯的敌人。
**塔会挡路**——你摆的不是炮位，而是整张迷宫；同时每座塔都吃电，电力不够全场降速。

三条与常见塔防拉开距离的设计：

1. **动态迷宫（mazing）**：塔与反应堆占据格子、阻断地面敌人的行进路线。每建一座塔，
   全局寻路场立刻重算，敌人改道。只要留得下通路就能建——摆歪了就是给敌人修高速。
2. **电力预算**：第二资源 `power`。攻击塔吃电，**反应堆**产能。电力超载 = 全场「欠压」
   （火力整体变慢，见 §6），逼你在"多建一座塔"和"多拉一座电"之间取舍。
3. **主动技「空袭」**：玩家不只看戏——冷却型空袭击可定点清场（§7）。

胜负：撑过 **20 波** 即通关；磁芯血量归零即失败。开启**无尽模式**后第 20 波不再判通关，
继续出第 21、22… 波（按威胁预算生成、血量递增），直到磁芯失守。

## 1. 世界与坐标系

| 项 | 值 | 说明 |
|---|---|---|
| 内容区 | 固定 `80×45` 格 | 主机固定，与主题无关 |
| 侧栏 | `w = 22`（另加 1 列分隔线） | 面板见 §9 |
| 可玩区 | `playfield()` → `px,py,pw,ph` | 初始 `pw = 80-22-1 = 57`，`ph = 45` |
| 网格 `MW×MH` | **等于可玩区尺寸**（初始 57×45） | `init` 时取一次 `playfield()` 定尺寸；一格 = 一个字符 |
| 时间基准 | 逻辑帧固定 60Hz，`dt` 秒 | 所有速度用「格/秒」、冷却用「秒」 |
| 随机 | 一律 `phos.sys.random` | 可复现：同 seed 同地图同波次 |

坐标：地图格 `(x, y)` ∈ `[0,MW) × [0,MH)`，`(0,0)` 在可玩区左上角。
绘制时统一 `screen.put(px + x, py + y, ...)`。

**地图风格（开局菜单选，见 §5.0）**：`OPEN`（岩石稀疏）/ `CANALS`（水道+桥）/
`MAZE`（岩石密、绕）/ `RANDOM`（以上随机取一）。生成走 `map.lua`：

1. 四周加一圈岩石边框，留出左侧的 **1~3 个刷怪口**（`OPEN` 1 个、`CANALS` 2 个、`MAZE` 2~3 个）
2. 按风格撒岩石 / 水块（值噪声式成簇，非逐格乱撒），避开磁芯附近
3. 磁芯放在**右缘内侧** `(MW-3, MH/2)` 的 1 格（`CORE`）
4. **连通性兜底**：对每个刷怪口做 BFS，若到不了磁芯，逐簇回退挖除障碍，直到全通
5. 生成结束时缓存第一张地面寻路场（§4）

## 2. 地形与格子类型

一格只有一种类型（`map.cell[y][x]` 存单字节）：

| 类型 | 字符 | 可走（地面） | 可建 | 颜色槽（`phos.color.*`） |
|---|---|---|---|---|
| `GRASS` 空地 | `·`（稀疏点点，其余留空） | ✅ | ✅ | `dark_gray` |
| `ROCK` 岩石 | `#` | ❌ | ❌ | `gray` |
| `WATER` 水 | `~` | ❌ | ❌ | `blue` |
| `GATE` 刷怪口 | `S` | ✅（敌人出生点） | ❌ | `magenta` |
| `CORE` 磁芯 | `@` | ✅（敌人终点） | ❌ | 血条色（§6） |
| `TOWER` 塔/结构 | 见 §6 字符 | ❌ | ❌（已占用） | 见 §6 |

- 水只挡地面单位，**飞行敌人无视一切地形**（§5.3）
- 塔与反应堆落格后该格变为 `TOWER`，地面寻路把它们当墙
- **地形不可破坏**：`ROCK`/`WATER` 只在开局生成时被改写过，进入游戏后**永不变**。
  游戏内会被拆掉的**只有建筑**——玩家建的塔 / 反应堆 / 采矿机（§6.7）。
  敌人说的"拆墙"指的是拆**你用塔砌成的迷宫**，**绝不是**岩石 `#`。

## 3. 玩法状态机

`main.lua` 持一个 `phase`：

| phase | 说明 | 出口 |
|---|---|---|
| `menu` 开局菜单 | 选难度 / 地图 / 无尽开·关 / 开始（§5.0） | 按 A 进入 `build` |
| `build` 布防期 | 倒计时，可建/拆/升级、可提前放波 | 倒计时归零或按 `space` → `combat` |
| `combat` 战斗期 | 波次进行，仍可建/拆（敌人已入场）、仍可按 `space` **提前招下一波** | 全部敌人清空 **且所有出怪表出完** → `build`（或 `won`；无尽模式永远回 `build`） |
| `won` 通关 | 20 波清完（**仅非无尽**） | 按 A 重开（新 seed） |
| `over` 失败 | 磁芯 ≤ 0 | 按 A 重开（新 seed） |

- `combat` 期建塔同样触发重寻路（敌人当场改道）——这是核心博弈点
- **提前放波（§6.4）**：`build` 期按"省下的等待比例"发等待金；`combat` 期也能按 `space` 招下一波
  （发**满额**等待金），但**场上最多同时两拨**
  （两拨都还在——有活口或还没出完——就不能再招，直到某一拨被清干净）
- `won` / `over` 时暂停推进（`game:update` 直接返回）

## 4. 寻路场（`map.lua`）

**地面**：从磁芯做一次 **BFS**（4 邻接），得到 `dist[y][x]`（到磁芯的步数）。敌人每步
移动到 `dist` 更小的邻居（`GRASS`/`GATE`/`CORE`）；平局按固定顺序（左→右→上→下）取，
保证确定性。塔落格后**重算 BFS**（网格 ≤ 57×45 = 2565 格，BFS < 0.2ms，远低于 100ms 看门狗）。

- `map.ground_path_exists()`：所有刷怪口是否都能到磁芯（观测用；不再用于建塔校验）
- `map.can_build(x,y)`：**只看地形 = `GRASS`**（纯地形）；"这一格有没有敌人站着"由 game 叠加。
  **不再因"会堵死"拒绝建造**——允许把磁芯整个围死，由怪物自己拆墙开路（§5.5 / §6.7）
- `map.assault_field(tx,ty)`：从某座塔出发的 BFS 场，敌人拆塔时据此走到塔相邻格
  （按地图 `version` 缓存，多只敌人共享；地形一变即失效）
- **禁死角**：BFS 天然不会造死角；`ground_path_exists` 仍供观测"玩家是否把路封死"

**飞行**：不走寻路场，直接朝磁芯直线插值（§5.3）。

## 5. 波次与敌人

### 5.0 开局菜单（`menu`）

上下键选择、左右键改值；最底两行是 START 与（有存档时）CONTINUE：

| 行 | 取值 | 默认 |
|---|---|---|
| DIFFICULTY | `EASY` / `NORMAL` / `HARD` | `NORMAL` |
| MAP | `OPEN` / `CANALS` / `MAZE` / `RANDOM` | `RANDOM` |
| ENDLESS | 开 / 关 | 关（上次选择，存盘 §9） |
| START | 按 A 开始 | — |
| CONTINUE | 按 A 继续存档（**仅当 `save` 非空时出现**；`save_used=="1"` 变灰不可选） | — |

难度影响 §5.4 的系数表。菜单行号登记在 `main.menu_rows`（漏登记 = 那一行永远选不到）；
`CONTINUE` 是**条件行**——无存档时不存在，导航自动跳过（`menu_input` 按现存的 row 走）。

### 5.1 波次数据（`waves.lua`）

一波 = 若干「组」：`{ type, count, interval, gate }`（`gate` 省略 = 随机刷怪口）。
生成器按波号取模板（下表为 20 波），并对 `hp`/`speed`/`reward` 乘 §5.4 的成长系数。

| 波 | 内容（type ×count @ 间隔秒） |
|---|---|
| 1 | grunt×6 @1.0 |
| 2 | grunt×10 @0.8 |
| 3 | runner×8 @0.7 |
| 4 | grunt×8 @0.7 + runner×6 @0.6 |
| 5 | armor×4 @1.5 |
| 6 | swarm×20 @0.25 |
| 7 | flyer×6 @1.0 |
| 8 | grunt×12 @0.7 + armor×4 @1.4 |
| 9 | shield×5 @1.2 |
| 10 | **boss×1** + grunt×8 @0.8 |
| 11 | runner×14 @0.5 |
| 12 | swarm×30 @0.2 + flyer×8 @0.9 |
| 13 | armor×8 @1.2 |
| 14 | shield×8 @1.0 + grunt×10 @0.7 |
| 15 | **boss×1** + flyer×10 @0.8 + runner×10 @0.6 |
| 16 | swarm×40 @0.18 + armor×6 @1.3 |
| 17 | shield×10 @0.9 + flyer×10 @0.8 |
| 18 | armor×12 @1.0 + runner×16 @0.5 |
| 19 | grunt×20 @0.5 + armor×10 @1.0 + shield×8 @0.9 + flyer×10 @0.7 |
| 20 | **boss×2** + swarm×40 @0.18 + armor×10 @1.0 |

- 组内按 `interval` 出怪；多组并行（各自计时器）
- `wave` 计数只在**首组开始出怪**时 +1；清空全部敌人后进 `build`

**无尽波（w > 20，仅无尽模式）**：不再用模板，按**威胁预算**现算。

- 预算 `B(w) = B20·(1 + ENDLESS_RATE·(w-20))`，`B20 = 116`（第 20 波模板威胁总量），
  `ENDLESS_RATE = 0.159`（模型第 15→20 波平均增幅，§5.4.1）——与血量**同源外推**，不另拍一套
- 敌人威胁点：`grunt 1 / runner 1 / swarm 0.4 / flyer 2.5 / shield 3 / armor 4 / boss 30`
- 反复从"剩余预算买得起的类型"里随机挑一个花掉；买不动（剩余 < 最小项 0.4）就停；
  `boss` 每波最多 2 个。每个类型配一个出怪间隔（沿用现有量级，见 `Waves.THREATS`）
- 随机一律 `phos.sys.random`：同种子同波次生成完全一致（可复现）

### 5.2 敌人类型（`enemies.lua`，数据驱动）

基础值（未乘成长系数）；`armor` = 每击固定减伤；`leak` = 走到磁芯时扣的磁芯血。

| type | 字符 | 颜色 | hp | armor | 速度(格/s) | leak | 赏金 | siege | 机制 |
|---|---|---|---|---|---|---|---|---|---|
| `grunt` 步兵 | `o` | `red` | 60 | 0 | 1.6 | 1 | 5 | 3 | 基准 |
| `runner` 快兵 | `r` | `yellow` | 40 | 0 | 3.2 | 1 | 6 | 2 | 快，血量低 |
| `swarm` 虫群 | `.` | `magenta` | 25 | 0 | 2.4 | 1 | 2 | 1.5 | 海量、脆 |
| `armor` 装甲 | `A` | `gray` | 220 | 5 | 1.0 | 2 | 13 | 6 | 固定减伤（电/火无视） |
| `shield` 护盾 | `D` | `cyan` | 140 | 0 | 1.4 | 2 | 15 | 4 | +40 护盾，2s 未受击后 6/s 回充 |
| `flyer` 飞行 | `v` | `green` | 90 | 0 | 2.0 | 2 | 10 | 3 | 无视地形与塔，直线扑磁芯 |
| `boss` 首领 | `B` | `red`(`white` 描) | 2600 | 8 | 0.8 | 10 | 170 | 12 | 每 5 波；顶部血条 |

`siege` = 拆塔 DPS：走到塔相邻格后按 `siege × dt` 扣塔的 hp（§6.7）。
**刻意压低**——塔 hp 只有 70–140，单只小怪拆一座塔要十几秒、一群围攻也要数秒，
这样塔被攻击时**挡得住**（有"顿感"），不会一触即碎；围攻堆积才会真的拆开。

**伤害结算**：`eff = max(1, dmg - armor)`。`armor` 只对 `GUN`/`CANNON` 生效；
`TESLA`/`FLAME` 标记 `ignore_armor`，对装甲打满。

**状态效果**（敌人身上各一个计时器）：
- `slow`：来自冰塔，`factor`（0.55 = 减速 45%）、`t` 秒
- `burn`：来自火焰，`dps` 6/s、`t` 秒（不吃护甲）

### 5.3 移动

- 地面：每帧沿 `dist` 梯度走，速度 × `slow_factor`；到 `CORE` 格即 `leak` 并销毁
- 飞行：`(x,y)` 朝磁芯按速度直线推进（不受地形/塔影响），到磁芯即 `leak`
- 敌人 `x,y` 存**浮点**（格坐标，格中心 +0.5 对应绘制格），便于平滑移动
- 敌人互相**不碰撞**（穿过彼此，避免堵死）

### 5.4 成长与难度系数

血量/赏金**不再手拍逐波表**：改由 §5.4.1 的**难度模型**在加载期逐波推导（waves.lua 里
只留少量具名常量 + 模型方程）。速度仍走一条独立缓坡（快慢是风味，强度由模型定）。

| 系数 | 来源 | 形态 |
|---|---|---|
| hp 乘数 `hp_growth(w)` | 模型推导（§5.4.1） | 随模板组成起伏（见下表），使 `E(w)/P(w)=R·S(w)` |
| 速度乘数 | `min(1.25, 1 + 0.012·(w-1))` | ×1.00 → ×1.23 |
| 赏金乘子 `reward_growth(w)` | `1 + 0.20/(20-1)·(w-1)` | ×1.00 → ×1.20（不滚雪球） |

**同一波对所有玩家强度一致**：模型取**中位数玩家强度**，不做任何局内动态调节。

**无尽波（w > 20）**：血量 = `hp_growth(20)·(1 + ENDLESS_RATE·(w-20))`，
`ENDLESS_RATE = 0.159`（模型在第 15→20 波的平均每波增幅，见 §5.4.1）；威胁预算与血量
**同源外推**（§5.1）。速度/赏金仍走上面两式。

难度（开局菜单）：

| 难度 | 起始金币 | 磁芯血 | 敌人 hp 乘数 | 敌人速度乘数 | 模型 E/P 区间 |
|---|---|---|---|---|---|
| EASY | 170 | 25 | ×0.80 | ×0.90 | 1.20 → 2.01 |
| NORMAL | 130 | 20 | ×1.00 | ×1.00 | 1.84 → 2.54 |
| HARD | 120 | 15 | ×1.15 | ×1.05 | 2.24 → 2.92 |

起始金币按"够撑过前几波"定：HARD 120 足以开局两台机枪/一枪一炮（E/P≈2.2，紧但不秒崩）；
EASY 170 更宽松。hp 乘数按各档松紧叠在模型曲线之上（模型曲线本身只描述 NORMAL）。

### 5.4.1 难度模型：经济 → 我方火力 → 敌人强度

目标：让**难度曲线**（敌人总强度 ÷ 玩家总火力）全程平缓、后期缓升，而不是"开局平顺→
某波突然崩"。做法：从"中位数玩家到第 w 波能攒多少钱、能买多少火力"反推"第 w 波该有多强"。

**方程**（`w` = 波号；输入量全部来自 TEMPLATES 与 `MODEL_ENEMY`，见下）：

```
FPC     = median over 攻击塔 of  F/cost
          F = dps·range；连续塔取 dps；AoE 乘 (1+splash)；连锁乘 chain 数
I(w)    = credits0 + Σ_{i≤w}[ Σ_type countᵢ·bounty·reward_growth(i) + (15+2i) + INCLUDE·P_MED·max_bonus(i) ]
P(w)    = I(w)·FPC·EFF                              我方累计火力
Ebase(w)= Σ_type count·(hp + ARMOR_W·armor + shield) 敌人基础总血
Etarget(w) = P(w)·R·S(w)，  S(w) = 1 + S_SLOPE·(w-1) 目标敌人强度
hp_growth(w) = Etarget(w) / Ebase(w)                 逐波推出
```

于是 `E(w)/P(w) = R·S(w)`：**与模板无关地**保持近似恒定、随 S 缓升（下表证明）。

**常量表**（含义 + 取值理由）：

| 常量 | 值 | 含义 / 理由 |
|---|---|---|
| `FPC` | 2.1758 | 攻击塔 F/cost 中位数；现行中位塔 = TESLA（`24/1.40·5.5·3/130`）。改 towers 要重算 |
| `EFF` | 0.50 | 中位数玩家把金币转成"有效火力"的效率（布局/空转/超杀/欠压/辅助设施） |
| `ARMOR_W` | 20 | 每点 armor 折算的等效血：armor=5 使装甲等效血约 ×1.45 |
| `S_SLOPE` | 0.02 | 目标松紧缓坡：后期略紧，不突变 |
| `R` | 1.8384 | 整体松紧常量，标定 `hp_growth(1)=1.0`（开局面值 → 平顺开局） |
| `HP_GROWTH_1` | 1.0 | 第 1 波血乘子基准（NORMAL） |
| `REWARD_MAX` | 1.20 | 赏金乘子全程上限；数量已驱动收入增长 ~18×，乘子再快就滚雪球 |
| `CLEAR_A/B` | 15 / 2 | 波清奖金 `15+2w`（与 `game.lua check_end` 同步） |
| `BUILD_TIME` | 60 | 每波等待秒数（`game.lua`；满额 = 整段都省掉） |
| `WAIT_A/B` | 10 / 2 | 满额等待金 `max_bonus(w)=10+2w`（`waves.wait_bonus_max`）；量级 ≈ 波清奖金 → 有意义但非主要收入 |
| `P_MED` | 0.50 | 中位实现比例：玩家不总提前招、常建到一半才招 → 中位拿到满额一半 |
| `INCLUDE` | 0.50 | 等待金折入 I(w) 的比例（只按一半计入怪物强度：手感奖励 > 曲线影响） |
| `ENDLESS_RATE` | 0.1588 | 无尽每波强度增幅（模型第 15→20 波平均） |

等待金折入的是 `INCLUDE·P_MED·max_bonus(w) = 0.25·(10+2w)`：全程约 **+155 金**
（w20：4710 vs 4555，约 +3.4%）。对照**上一版模型**：旧 `early_est=5+(3+w)=8+w` 偏大（全程 ~370），
新规则下折入额反而更小（~155）→ `R` 由 1.78 升到 1.84、三档 `E/P` 整体约 +4%（如 NORMAL
w1 1.78→1.84）。这正是"等待金只按一半计入"的直接结果：**新规则下玩家可拿的等待金整体更大
（后期与 combat 尤其明显），但模型只让怪物曲线吸收其中 `INCLUDE·P_MED = 25%`**。

`dev/balance_model.py` 是**同一模型的独立复算**：打印三档完整表 + E/P 校验，并做
enemies.lua / towers.lua / waves.lua / 本文件的数值**同步自检**（防三处漂移）。

**关于 `hp_growth` 为何"起伏"而非单调**：`E/P` 平缓的代价就是 `hp_growth` 必须**逐波抵消
模板组成的落差**——boss/精英波基础血高，乘子就低；runner/虫群波基础血低，乘子就高。
玩家能感到的是最终**总强度 E(w)/P(w)**（平滑上升），而不是这条内部乘子。若强行把
`hp_growth` 抹成单调，`E/P` 会摆动 **4~10 倍**（`balance_model.py` 记录了该实验），
等于把"某波突然崩"重新放回来。

**与 enemies.lua 的关系（防漂移）**：`waves.lua` 自带一张最小镜像表 `MODEL_ENEMY`
（只含 hp/armor/bounty/shield）与 FPC 常量，让 waves 保持"纯数据、不认识敌人实体"的边界
（DESIGN §11）。**改 enemies.lua 的 hp/armor/bounty 或 towers.lua 的火力/造价，必须同步
waves.lua 的 `MODEL_ENEMY` / `FPC` 与 dev/balance_model.py 的对应表**（三处一致）。
取舍：宁可三处各留一份最小副本，也不让 waves 去 `require("enemies")`（那会破坏模块边界、
且换一份 waves.lua 就不再自洽）。

### 5.5 敌人 AI：目标优先级（`enemies.lua`）

**每个敌人独立**，每 **0.5s** 或状态变化（目标塔倒塌）时重选目标；
**正在拆某座塔时不切换**（直到它倒塌或不再挡路）。目标自上而下，首个成立者胜：

| 优先级 | 触发条件 | 目标 |
|---|---|---|
| **P0 拆塔** | 到磁芯不可达（`path_dist < 0`），或 `path_dist > 3 × 曼哈顿距离(到磁芯格)` | 最近的挡路塔（4 格内最近的一座；没有就近的取全局最近的塔）；走到其相邻格按 `siege` 拆。**拆的是塔，不是地形** |
| **P1 有价值建筑** | 8 格侦察半径内存在 `REACTOR`/`MINER` | 最近的**那一座**（打掉断你的电/钱）；拆完 / 离开侦察圈后重评 |
| **P2 磁芯** | 默认 | 沿现有 BFS 寻路场冲击磁芯 |

- `path_dist` = `map:dist_at(格)`；曼哈顿 = `|ex - core.x| + |ey - core.y|`
- **飞行单位**不做 P0（飞越地形），但做 P1（顺路拆反应堆/采矿机），否则直冲磁芯
- 拆塔：走到目标塔**相邻格**，每帧按 `siege × dt` 扣它的 hp；塔受击时闪红（view）
- 原"被堵死就直线飞磁芯"的兜底**已删除**，改由 P0 处理
- 拆塔走位用 `map.assault_field(塔格)`（BFS 到塔相邻格）；到不了时的极端兜底是朝塔直走

### 6.2 升级（最多 L3）

升级效果**每型由 `up` 档案声明**（见 §6.1 升级档案表），`Towers.stats(t,aura)` 读它算出
有效 `(dmg, range, interval)`——不再全场统一 `×1.6 / +1.5 / ×0.88`：

- 三轴**默认**：伤害 `×1.6`、射程 `+1.5` 格、攻击间隔 `×0.88`（`up` 未给该键时生效）
- 每型可覆写：`up.dmg`（`1.0` = 不涨）、`up.rate`（`1.0` = 不涨）、`up.range`（`0` = 不涨）
- 特殊轴（溅射/连锁/锁定/线宽/减速/光环…）用按等级数组成员，`Towers.by` 取
- **电力占用每级成长按类型**：多数塔 `+1`、**采矿机 `+2`**（`power_growth`）；反应堆升级只抬电力上限（`cap`：L2 +16、L3 +24）
- 面板、射程圈、开火结算**一律走 `Towers.stats`**：不写死任何一轴的倍率

升级花费：`upgrade_cost(L→L+1) = ceil(base_cost × 0.8)`（L2）、`ceil(base_cost × 1.2)`（L3）。
**拆塔返还**：累计投入（造价+已花升级费）的 **60%**（向下取整）。

### 6.3 目标选择（每座塔一个优先级）

按优先级从射程内敌人中选：

| 优先级 | 规则 |
|---|---|
| `FIRST`（默认） | 地面取 `dist` 最小（最靠近磁芯）；飞行取离磁芯最近 |
| `STRONG` | 当前 hp 最高 |
| `CLOSE` | 距塔最近 |
| `AIR` | 优先飞行单位，其次 `FIRST` |

`P` 切换选中塔的优先级（`FIRST→STRONG→CLOSE→AIR→FIRST`）。
侧栏"已选"详情里有一行 `优先 / PRIORITY` 显示**现选值**（本地化短名：先攻/最强/最近/对空 ↔
FIRST/STRONG/CLOSE/AIR）——按 P 不再"看不见改了什么"。

### 6.4 资源与电力

- **金币 `credits`**：杀敌赏金 + 波清奖金 `15 + 2·wave` + 提前放波奖金（等待金）+ 
  **采矿机**周期产出（`{5,9,14}` 金 / 6s，按级；不随波次膨胀）
- **提前放波奖金（等待金）**：每波等待 `Game.BUILD_TIME = 60s`。满额曲线放在数据层
  `waves.wait_bonus_max(w) = 10 + 2·w`（与波清奖金 `15+2w` 同量级、略低 → **有意义但非主要收入**）。
  - **build 期**提前招"所招波"：`bonus = round( clamp(剩余秒 / 60, 0, 1) × max_bonus(w) )`
    ——剩得越多拿越多：刚进布防就招 ≈ 满额，快等完才招 ≈ 0。
  - **combat 期**（上一波没清完就招下一波）：**满额** `max_bonus(w)`——整段等待都省掉了。
  - 于是 **combat（顶额）≥ build 末期**；场上最多同时两拨（两拨都在就不能再招）。
  - 该奖金约**一半**折入怪物强度曲线（`INCLUDE·P_MED`，见 §5.4.1）：手感奖励 > 曲线影响
- **电力 `power`**：`used` = 所有塔的 `power` 之和（每级 `+power_growth`，多数 +1、采矿机 +2）；`cap` = `8（基础）+ 反应堆产出`
- **欠压（brownout）**：当 `used > cap`，按**超出上限的比例** `over = (used-cap)/cap` 降载：
  **攻速 / 射程 / 连续伤 / 雷达光环** 一律乘 `max(0.2, 1-over)`——超出多少、削多少。
  侧栏电力行**变红闪烁 + 后缀 `-NN%`**，下一行盖过状态读数显示「电力超限！设施降载」
- 建塔金币不足时禁止；**欠压是策略选择**，不禁止

### 6.7 塔血量与倒塌

- 每座塔有 `hp` / `max_hp`（满值见 §6.1，独立于造价）
- 敌人站到塔相邻格后按 `siege × dt` 扣它 hp（AI 见 §5.5）；塔受击时**闪红**
- 塔 hp → 0：**倒塌**——该格还地、`compute_field()` 重算、从 `towers` 移除、**无返还**，
  并给一个倒塌特效（灰 `x` 环）+ 事件（`tower_down`）
- 侧栏：光标选中塔时显示其 **HP 条 + 数值**（色随血量档）

### 6.8 特效（`ctx.add_fx` → `view.lua` 按 `kind` 画）

所有特效统一走 `ctx.add_fx(eff)`、由 `view.lua` 用 `S.blend` **叠画**（压在世界之上、不抹底下的字形），
颜色只取色板槽。`fx` 有 `t` 计时，`game.fx_tick` 每帧递减、归零即回收——**不放超长命的效果**。
`total` 字段给需要"进度"的 kind（圆环扩张 / 抛物弧）。

| kind | 来源 | 画法 |
|---|---|---|
| `shot` | GUN / CANNON 弹道 | 沿 `(x0,y0)→(x1,y1)` 一串 `·`（交替 `-`）的曳光 + 塔口一个 `+` 枪口闪 |
| `boom` | CANNON 溅射 / 空袭 / 炮弹落地 | **扩张圆环** + 中心 `@` 亮点 + 几点 `+`/`x`/`·` 爆屑（半径随进度变大） |
| `dmg` | 任何造成伤害 | 目标格一个红 `·`（`amount ≥ 1` 才画） |
| `frost` | FROST 命中 | **冰爆**：目标格向外扩散的 `*`/`+`/`·` 雪花碎片（六个方向，短促） |
| `chain` | TESLA 连锁 | 逐段**锯齿闪电**：沿两点间逐格垂直抖动偏移，头 `@` 亮、尾 `/ \` 暗 |
| `flame` | FLAME 灼烧 | **火舌/火锥**：从塔口朝目标喷一簇 `*`/`^`，用 `t` 做抖动（不再是单环） |
| `laser` | LASER 贯穿 | 细密**光点束**：沿直线一串小点 `·`（与电塔的 `/ \` 锯齿闪电刻意区分），`thickness` 越大点越多条并行，亮头收尾 |

| `shell` | MORTAR 抛射 | **抛物线弧**：由 `(x0,y0)→(x1,y1)` 与进度 `1 - t/total` 在 view 里纯函数算弧上点（一个 `o` + 拖尾 `·`） |

## 9. 存档（`save = true`）

| key | 值 | 时机 |
|---|---|---|
| `best_wave` | 曾到达的最大波号（字符串数字） | 每次进 `combat` 或失败/通关时取 max 后写 |
| `wins` | 通关次数 | 通关时 +1 |
| `best_score` | 单局最高（金币峰值 + 波数×100） | 每帧结算、刷新即写（拔卡退出也算） |
| `speed` | 上次游戏速度（1/2/3） | 改速度时写 |
| `diff` | 上次难度 | 菜单确认时写 |
| `map` | 上次地图风格 | 菜单确认时写 |
| `endless` | 上次无尽开关（`"1"`/`"0"`） | 菜单确认时写 |
| `save` | 当前对局的**单行快照**（见 §9.1） | 按 `S` 时写 |
| `save_used` | `"0"` = 可继续 / `"1"` = 已用 | 见 §9.1 消耗规则 |

**最高分共用一格**：`best_wave` / `best_score` 非无尽与无尽**共享**，谁高算谁——不另开键。
只在**纪录刷新 / 设置变更**时写盘，不每帧 IO。

### 9.1 存档 / 继续（`S` 存、菜单"继续"读）

**一次存档只有一次继续机会**。对局中按 `S`（`s` 未被占用）→ `Game:snapshot()` 写 `save`、
`save_used="0"`、照常 `settle_score()`、回菜单。"继续"入口出现在菜单"开始"**下面**，
仅当 `save` 非空时出现；`save_used=="1"` 时该行**变灰、不可选**（按 A 给拒绝音、不载入）。

**消耗规则**（何时把 `save_used` 置 `"1"`）：

| 时机 | 说明 |
|---|---|
| 载入"继续"时 | 一次机会用掉：`Game.restore(read("save"))` → `play`，立即写 `save_used="1"` |
| 一局结束（`ev.over` / `ev.won`） | 已输/已通关的对局不能"继续"回去 |
| 退格回菜单（"主动结算"） | 主动放弃本局 = 一并消耗 |
| 按 `S` | **不消耗**：写的就是 `save_used="0"`，回菜单后"继续"仍可点 |

于是：`S` 存档 → 菜单"继续"可点；`继续`一次后变灰；再按 `S` 又可继续。

**快照格式**（`Game:snapshot()` 返回**单行**字符串；`\n` 禁用——`save_store` 校验）：
记录用 `;` 分、字段用 `,` 分；浮点一律 `string.format("%.3f")`，读回 `tonumber`；布尔存 `0/1`。
零/默认值字段**留空**（`tonumber("")==nil` 天然回落默认）以塞进 4096 字节值长上限。

| 记录 | 内容 |
|---|---|
| `H` | 标量：`diff, map_style, endless, core_max, core_hp, credits, peak_credits, phase, wave, wave_total, build_timer, next_in, airstrike_cd, heal_count, towers_lost, build_index, cx, cy, banner, rng_seed` |
| `M` | 地图元信息：`w, h, core.x, core.y, version` |
| `C` | 地图全部格（**RLE**：`<值 0..5><游程>`，游程写 a..z 双射 26 进制；数字与字母不相交、无需分隔符） |
| `G` | 刷怪口列表 `n` + 每口 `x,y` |
| `S` | 出怪表：每波 `wave` + `factors{hp,speed,reward}` + 每组 `{type 下标,count,interval,gate,spawned,timer}` |
| `T` | 塔：`type 下标,x,y,level,cd,kills,priority 下标,spent,hp,max_hp,hit_t` + 地狱塔 `locked`（敌人下标+`heat`） |
| `E` | 敌人（`Enemies.new` 全字段 + `wave,mode,reason,retarget_t,dead,leaked` + `target` 塔下标） |
| `K` | 空袭预警 `{x,y,t}` |

- **引用解析**：先建 `towers` → 再建 `enemies`（`enemies[i].target` 解析为 `towers[下标]`）→
  最后把每座地狱塔 `locked` 里的**敌人下标**解析回对象；非法/缺失下标一律置 `nil`（不崩）。
- 重建后 `map:compute_field()`、`Game:compute_power()`、清 `map.af_cache`（`Map.from_snapshot`
  走**生成之外**的路径，不消耗随机）。
- `fx`（瞬时特效）与 `ev`（每帧重建）**不入快照**。

**RNG 无法精确续流（如实声明）**：主机没有读取当前 RNG 状态的接口，`Game:snapshot()` 只能存
一个 `rng_seed`，`restore` 时 `phos.sys.seed(rng_seed)` 一次——**续局后的随机流从该种子重开**，
而非精确接续存档前的流。因此"续局后同输入逐位复现"成立，但"续局与不存档一直玩下去完全同轨"
**不保证**。

**往返一致性**：`snapshot → restore → snapshot` 逐字一致。要点是浮点统一 `%.3f`（存档值经一次
取整，重存仍是同一串）、`rng_seed` 随快照存回、地图 RLE 可逆。载入发生在 `update` 的菜单分支里
（该帧不推进 `game:update`），故载入后立刻再 `S` 得到的就是原始恢复态，可逐字比对。

## 10. `debug_state()` 字段

供 agent 与自测读结构化状态，不必反推画面：

```lua
function debug_state()
  return {
    phase = phase,                 -- "menu"/"build"/"combat"/"won"/"over"
    wave = wave, wave_total = 20,
    endless = endless,             -- 无尽模式开关
    diff = diff, map_style = map_style,
    core_hp = core_hp, core_max = core_max,
    credits = credits,
    power_used = power_used, power_cap = power_cap, overload = (power_used > power_cap),
    speed = speed, next_in = next_in,       -- 秒（build 倒计时 / combat 剩余）
    enemies_alive = #enemies,
    selected_type = selected_type,          -- 建造面板当前塔型
    cursor_x = cx, cursor_y = cy,
    airstrike_cd = airstrike_cd,
    heals = heal_count, towers_lost = towers_lost,  -- 维修次数 / 被拆倒塔数（观测）
    buildable = map.can_build(cx, cy),      -- 光标格当前能否建造（纯地形 + 无敌人）
    towers = { { x=, y=, type=, level=, kills=, priority=, hp=, max_hp= } },  -- 一条一塔
    enemies = { { x=, y=, type=, hp=, max_hp=, fly=, dist=, mode=, reason=, tx=, ty= } },
                                            -- 一条一敌（mode="core"/"tower"，reason="wall"/"reactor"）
    -- 寻路/地图可观测性：agent 判定"我的墙有没有堵死路"不用读画面
    path_ok = map.ground_path_exists(),
    grid = { w = MW, h = MH },
  }
end
```

数值支持 number/string/boolean 与一层表；`towers`/`enemies` 写成数组。
菜单期另给 `menu_row`（当前高亮行 = `menu_rows` 常量）、`has_save`、`save_used`（§9.1）——
自测据此判断"继续"行是否出现/是否变灰、当前选中的是第几行。

## 12. 分期与验收

**第一刀（可玩核心）**：地图生成 + BFS 寻路 + GUN/CANNON + 1~5 波 + 金币 + 建/拆 +
磁芯血量 + 胜负。

**第二刀**：电力系统（反应堆 + 欠压）、升级与优先级、其余塔型与敌人类型、空袭、
侧栏与 HUD 完整读数、音效音乐。

**第三刀**：20 波平衡、地图 4 风格、存档、`debug_state`、双语文案、`~` 调试台挂
关键旋钮（起始金币、敌人 hp 系数、空袭伤害等）。

### 第一刀验收用例

1. 同 seed 生成的地图与波次完全一致（`phos.sys.random`）
2. 在唯一通路上建塔把路堵死 → 该次建造**允许**（can_build 只看地形），`path_ok` 可变 `false`；
   放波后敌人用 **P0** 拆墙开路、`towers_lost` 增加（不再是旧版"拒绝建造"）
3. GUN 能持续命中并击杀 grunt，赏金入账、`credits` 增加
4. CANNON 的溅射同时伤到相邻两敌
5. 敌人走到磁芯 → 磁芯血按 `leak` 扣减、敌人消失
6. 磁芯血归零 → `phase = "over"`；按 A 以新 seed 重开
7. 20 波清完 → `phase = "won"`，`wins` +1，`best_wave = 20`（**无尽模式不判通关**）
8. `debug_state` 的 `towers`/`enemies` 坐标与画面一致（agent 可据此驱动建造）

### 第三刀之后（无尽 / 拆塔 / 维修 / AI）验收

9. 无尽开启：越过第 20 波继续出怪，`max_wave > 20`，`phase ≠ "won"`；同 seed 波次可复现
10. 塔有 `hp/max_hp`；被围死的保护点会被敌人（P0）拆开，`towers_lost > 0`
11. 维修塔（REPAIR）确实治疗范围内受损友军，`heals > 0`，画面有绿色脉冲 + `+N`
12. 敌人（含飞行）在 8 格内发现反应堆/采矿机会顺路拆它（P1：`reason = "reactor"`，即"值钱建筑"类）
13. 对局中按 `S` → 菜单出现"继续"；`继续`后 `credits`/`wave`/塔数量与类型/核心血与存档前一致，
    载入即 `save_used=1`；快照为**单行**且 `snapshot→restore→snapshot` 逐字一致
14. 一局打完（`over`/`won`）→ `save_used=1`；退格回菜单也消耗；按 `S` 存的是 `"0"`（不消耗）

## 13. 与现有卡带的区分

现有出厂卡带：`ballbattle`（吃豆成长）、`bricks`（打砖块）、`chomp`（迷宫吃豆）、
`life`（元胞自动机）、`runner`（跑酷）、`snake`、`tetris`、`worms`（回合炮击）、
`xiangqi`（象棋）。**本卡带是唯一的实时网格塔防**，且以「动态迷宫 + 电力预算 + 空袭」
为差异点，题材与机制均不与任何一张重叠。
